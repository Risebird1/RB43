Build the Campaign Outcomes and Candidate Call Detail screens. Also give the developer the interactive pixel-spec file risebird-ai-phone-screen-demo.html (repo docs/demo/) — its buttons still say "Sync from VAPI"; use the provider-neutral labels from this document instead.

1 · Normalized call-result contract (the ONLY thing the UI binds to)

{
  "provider": "vapi",
  "callId": "019f...86093",
  "candidateId": 123,
  "candidateName": "Nandini Sharma",
  "candidateEmail": "nandini@example.com",
  "phone": "+917906314389",
  "status": "ended",
  "endedReason": "customer-ended-call",
  "startedAt": "2026-07-08T18:53:00Z",
  "endedAt": "2026-07-08T18:55:52Z",
  "durationSeconds": 172,
  "cost": 0.42,
  "recordingUrl": "https://.../call.mp3",
  "transcript": "plain text OR [{\"speaker\":\"ai|candidate\",\"text\":\"...\"}]",
  "summary": "recruiter-readable digest",
  "successEvaluation": "PASS",
  "structuredData": { "location_region": "Noida", "notice_period": "30 days", "any_key": "any value" },
  "raw": { "original provider payload, any shape" }
}

Contract rules the UI must implement

Field UI rule
provider Show as a small neutral chip (11px pill, e.g. VAPI, PLIVO) in the detail meta and optionally next to status in the table. Never affects layout or logic.
status Exactly four canonical values: queued · ringing · in-progress · ended. Backend adapters map provider statuses to these; the UI styles only these four.
endedReason Free text — display as-is under the status badge; do not enumerate.
successEvaluation Normalize for display: true/pass (any case) → PASS badge; false/fail → FAIL badge; numeric → show the score; anything else → neutral text; empty → —.
structuredData Arbitrary schema — render 100% dynamically. Iterate keys: prettify key (notice_period → Notice Period), value in a cell. null → —. Booleans → Yes/No. Nested object/array values → cell shows view JSON → linking to the Structured Output tab. Zero hardcoded field names — different campaigns/providers return different schemas.
transcript Support both shapes: plain string → one text block; array of {speaker, text} → chat bubbles (ai-ish speakers teal, others orange).
recordingUrl Any browser-playable URL (mp3/wav). Missing → recording area shows — and no player.
Any missing/empty field Graceful —; the layout must never break on partial data.
