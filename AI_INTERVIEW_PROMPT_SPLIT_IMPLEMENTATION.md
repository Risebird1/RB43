# AI Interview Prompts: Primary + Interview Evaluator

Skill channels flagged `IsAIInterview = 1` now carry **two** prompt ids instead of one, so that
conducting an interview and reporting on it can be driven by different stored prompts.

| Field (UI) | Column | Required | Job |
|---|---|---|---|
| Primary Prompt Id | `IRF.OpenAIPromptId` | Yes, when `IsAIInterview = 1` | Conducts the interview. For **adaptive** channels this is the question generator. Also writes the report when no evaluator prompt is set. |
| Interview Evaluator Prompt Id | `IRF.OpenAIEvaluatorPromptId` | No | Writes the candidate's report. |

The change exists to split adaptive interviews in two, but the Add/Edit UI is deliberately shared
between preset and adaptive, so both fields appear for every AI interview channel. The primary
field keeps the deliberately general name "Primary Prompt Id" rather than "Question Generator
Prompt Id" for that reason - on a preset channel it generates no questions.

**Preset question generation is untouched.** Preset papers still come from the channel's question
bank / question sets; no prompt generates them, before or after this change.

## Resolution order

Interview turns (adaptive `start` / `ask` / `asksystem`):

    IRF.OpenAIPromptId  ->  config OpenAI:AIInterviewerPromptId

Report generation (both preset and adaptive):

    IRF.OpenAIEvaluatorPromptId  ->  IRF.OpenAIPromptId  ->  config

where config is `OpenAI:AIInterviewPromptMap` on the preset path and
`OpenAI:AIInterviewerPromptId` on the adaptive path. The config step is the pre-existing
fallback and is unchanged; a channel that carries neither prompt behaves exactly as before.

Both hops are implemented once, in `OpenAIApiController.ResolvePromptIds`.

## Files changed

Database (`Risebird.DB`)
- `Migrations/Add_OpenAIEvaluatorPromptId_To_IRF.sql` - **new**: adds the column and backfills it.
- `Tables/IRF.sql` - column added to the create path and to the idempotent `IF NOT EXISTS` blocks.
- `StoredProcedures/usp_AddIRFDetails.sql`, `usp_UpdateIRFDetails.sql` - `@OpenAIEvaluatorPromptId`.
- `StoredProcedures/usp_GetAIInterviewDetailsBySessionId.sql` - returns the evaluator prompt.
- `StoredProcedures/usp_GetAIInterviewSpecificDetails.sql` - returns both prompts, and its
  `InterviewSessions` join became a **left** join so the first adaptive turn (which runs before a
  session row exists) can still resolve the channel's prompts.

Entities / repository
- `IRFVm` (both `IRFVm` and `IRF` classes), `MeetingVM`, `AddUpdateMeetingVM` - new property.
- `IRFRepository` - read + add/update parameters, plus `NormalizePromptIdForDb` so a blank field
  is stored as `NULL` rather than `''`.
- `AIInterviewerRepository` - reads the evaluator prompt for the preset report path.

Runtime
- `AssistantServiceHelper.GenerateAIInterviewerMessage` takes an optional `promptId`, falling back
  to `OpenAI:AIInterviewerPromptId`. Interface updated to match.
- `OpenAIApiController` - `start`/`ask`/`asksystem` pass the Primary Prompt Id; both report paths
  pass the evaluator-then-primary result.

UI
- `Views/IRF/Add.cshtml` - **both** fields added (Add previously had neither), plus the
  `CheckPrimaryPromptId` submit gate.
- `Views/IRF/EditIRF.cshtml` - primary field relabelled and marked mandatory, evaluator field
  added, same submit gate.
- `IRFController.AddIRF` / `IRFController.EditIRF` - server-side guard mirroring the client gate.
  The evaluator field is never validated: blank there is a supported state.

## Deployment order

1. `Migrations/Add_OpenAIEvaluatorPromptId_To_IRF.sql` (column + backfill).
2. `usp_AddIRFDetails.sql`, `usp_UpdateIRFDetails.sql`, `usp_GetAIInterviewDetailsBySessionId.sql`,
   `usp_GetAIInterviewSpecificDetails.sql`.
3. Application (`Risebird.Web`, `Risebird.Services`).

Steps 1-2 are backward compatible with the currently deployed application: the new stored
procedure parameters default to `null`, and the extra selected columns are ignored by the existing
`dt.Columns.Contains(...)` readers.

## Why the backfill

Before this change the single `OpenAIPromptId` column was labelled "Report Prompt Id" and was read
only by the preset **report** path. It now means Primary Prompt Id. The migration therefore copies
each AI interview channel's existing value into `OpenAIEvaluatorPromptId`.

This is behaviourally a no-op on day one - the evaluator falls back to the primary anyway, and both
hold the same value. It matters on day two: once someone repoints an existing channel's Primary
Prompt Id at a question generator, the explicit evaluator value keeps that channel's reports being
generated by the prompt that was already generating them. The backfill only touches rows whose
evaluator column is still empty, so it is safe to re-run.
