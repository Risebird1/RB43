WHAT THIS GUIDE COVERS
-----------------------
Changes needed in Relay to support:
  1. Extracting "skill_channel_id" from the email body (new field)
  2. Triggering resume ingestion for BOTH intents:
       - "New candidate submission"
       - "New interview request" (when NOT a new channel request)
  3. Passing "skill_channel_id" in the webhook payload so the server can skip
     the job-title scoring algorithm when the sender explicitly mentions
     their Skill Channel ID (e.g. QUADRJAVA5)

IMPORTANT — "New interview request" HANDLING:
  The system distinguishes between TWO scenarios under this intent:
  
  Scenario A: REQUEST TO CREATE A NEW SKILL CHANNEL
    - JD (job description) is attached → attachment_job_description = true
    - Server SKIPS resume ingestion (channel doesn't exist yet)
    - Ticket assigned to HR for manual channel creation
  
  Scenario B: ADDING RESUMES TO AN EXISTING CHANNEL
    - Resumes attached but NO JD → attachment_job_description = false
    - Server proceeds with resume ingestion (channel already exists)
    - Ticket auto-closed if ingestion succeeds
  
  Make sure the AI correctly sets attachment_job_description based on
  whether a JD document is attached.

NEW — PER-RESUME IRF ASSOCIATION (*** CRITICAL ***):
  When an email contains multiple resumes, they may be intended for DIFFERENT
  skill channels/roles. The AI must now extract a `resume_associations` array
  that maps EACH resume to its intended IRF.
  
  Structure:
  "resume_associations": [
    {
      "resume_url": "<Google Drive URL>",
      "resume_filename": "<original attachment filename>",   ← NEW
      "skill_channel_id": "<10-char code or null>",
      "job_title": "<role this resume is for>",
      "candidate_name": "<candidate name from filename/body>"
    }
  ]
  
  IMPORTANT: `resume_filename` must be the ORIGINAL attachment filename (e.g.,
  "John_Smith_Java_Developer.pdf"), NOT the Google Drive file ID/URL. This is
  displayed in the HR review modal when hovering over the resume link.
  
  The server will:
  1. Process each resume individually
  2. Match each resume to its specific IRF based on job_title or skill_channel_id
  3. Different resumes can go to different skill channels
  
  The old `resume_drive_urls` field is deprecated (set to []).

IMPORTANT — SKIP INGESTION WHEN primary_specialization IS NULL:
  If the AI cannot determine the primary_specialization (it's null/empty),
  the server will skip resume ingestion entirely and assign the ticket to an HR
  for manual review. This prevents incorrect IRF matching when context is unclear.

NEW — CANDIDATE SCHEDULE DATA EXTRACTION (*** See Part 8 in prompt ***):
  When candidates' interview slots are mentioned in emails:
  
  - Extract candidate_schedule_data array with 100% CONFIDENCE ONLY
  - Each entry must have: candidate_name, interview_date, interview_time, 
    skill_channel_id (10-char IRF ID), resume_drive_url, and resume_filename
  - `resume_filename` = original attachment filename (NOT the Drive URL)
  - Server will:
    1. Validate all fields
    2. Insert resumes with auto-schedule flag and extracted data
    3. Mark ticket as HasAutoScheduleCandidates = true
    4. Assign ticket to HR for review (NOT auto-scheduled)
  - HR reviews via "Review & Schedule" button on ticket dashboard
  - HR sees extracted data (from email) vs parsed data (from resume)
  - HR manually triggers scheduling after reviewing and validating
  
  This applies to "New candidate submission" and "New interview request" intents.

Background: A Skill Channel ID is always exactly 10 alphanumeric characters
(A-Z, a-z, 0-9). The server already validates it against the sender's eligible
list, so there is no security risk if a wrong ID is sent — it simply falls back
to the normal job-title scoring.

================================================================================
HOW THE SERVER USES skill_channel_id
================================================================================

When the server receives the webhook payload:

  1. It reads skill_channel_id from the payload.
  2. If skill_channel_id is present and exactly 10 characters:
       a. It looks for that ID in the sender's list of eligible IRFs.
       b. If found → uses that IRF directly. No scoring algorithm runs.
       c. If NOT found (wrong ID, cross-client, typo) → falls back to
          job-title scoring as normal.
  3. If skill_channel_id is null or missing → uses job-title scoring.

This means:
  - Emails where the client explicitly states the channel will be processed
    faster and more accurately.
  - Emails where the channel is ambiguous will still be matched via scoring.
