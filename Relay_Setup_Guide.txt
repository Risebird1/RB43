================================================================================
RELAY.APP SETUP GUIDE — CUSTOMER SUPPORT EMAIL TRIAGE
Risebird Portal Integration
================================================================================

PRE-REQUISITES
--------------
• A Relay.app account (free tier is sufficient to start).
• Your customer-support email inbox connected to Relay
  (Gmail / Outlook Mail both supported natively).
• Your Risebird portal deployed and accessible at a public URL,
  e.g. https://portal.risebird.io

STEP 1 — Connect your support email inbox
------------------------------------------
1. Log in to https://run.relay.app
2. Click "Apps" in the left sidebar
3. Search for "Gmail" (or "Outlook Mail", whichever your support inbox uses)
4. Click the app → click "Connect" or "Add account"
5. An OAuth popup will open — sign in with the Google/Microsoft account
   that owns your support inbox (e.g. support@risebird.io)
6. Grant the requested permissions and you will be redirected back to Relay.
   The connection will appear as active under the app's connections list.

   TIP: You can also skip this step entirely and connect the account
   on-the-fly when configuring the trigger in Step 4 — Relay will show
   a "Connect account" button right inside the trigger configuration panel.

STEP 2 — Create a new Agent
----------------------------
1. From the Relay workspace home, click "+ New" → "Agent"
2. Name it:  "Customer Support Email Triage"
3. (Optional) Give it a short description:
   "Reads inbound support emails, classifies intent, and notifies the Risebird portal."
4. Click "Create Agent"

STEP 3 — Create a new Workflow inside the Agent
------------------------------------------------
1. Inside the agent page, click "+ New Workflow"
2. Name it:  "Email Received → Classify & Forward"
3. Click "Create"

STEP 4 — Configure the Email Trigger
--------------------------------------
1. In the Workflow Editor, click "Add a trigger"
2. Select the email app you connected in Step 1 (Gmail / Outlook Mail)
3. Choose trigger type: "Email received"
4. Select the connection / account you linked in Step 1
   (your support inbox, e.g. support@risebird.io)
5. (Optional) Add a filter to only capture emails sent TO your support address:
     Field: "To"    |  Condition: "contains"  |  Value: support@risebird.io
6. Click "Save trigger"
7. Verify the Trigger Preview table shows recent emails from that inbox.

STEP 5 — Add an AI step to classify the intent
-----------------------------------------------
1. Click "+ Add step" below the trigger
2. Search for "AI" → select "AI" (this is Relay's built-in AI action)
   OR choose "OpenAI" → "Chat completion" if you prefer a specific model
3. Configure the step:
   • Model:       GPT-4o  (recommended for accuracy)
   • System prompt:
       (Paste the entire contents of  Relay_CustomerSupport_Agent_Prompt.txt
        from this repository — the section under "PURPOSE" through "TONE")
   • User message (prompt):
       From: {{trigger.from_email}}
       Subject: {{trigger.subject}}
       Received: {{trigger.date}}
       Body:
       {{trigger.body_text}}

       Based on the instructions above, classify this email and return ONLY
       a JSON object with a single key "intent" containing your classification.
       Example: {"intent": "Interview Scheduling Issue"}

   • Output format: JSON  (enable "JSON response" / "structured output" if shown)

4. Click "Save step"
5. Test the step by clicking "Test" and verifying it returns a valid intent.

STEP 6 — Add a Custom HTTP Request step to call your webhook
-------------------------------------------------------------
1. Click "+ Add step"
2. Search for "HTTP" → select "Custom HTTP Request"
3. Configure:
   • Method:   POST
   • URL:      https://portal.risebird.io/SupportTicket/Webhook
               (replace domain with your actual portal domain)
   • Headers:
       Content-Type:    application/json
       X-Relay-Secret:  REPLACE_WITH_YOUR_STRONG_SECRET
       (Use the SAME value you put in appsettings.json → RelayWebhook:Secret)
   • Body (JSON):
       {
         "sender_email":  "{{trigger.from_email}}",
         "subject":       "{{trigger.subject}}",
         "mail_content":  "{{trigger.body_text}}",
         "received_at":   "{{trigger.date}}",
         "intent":        "{{steps.[AI step name].output.intent}}"
       }
     Note: Replace [AI step name] with the actual name Relay assigns to Step 5.
           In Relay's variable picker it will appear under the AI step's output.

4. Click "Save step"

STEP 7 — Test the full workflow end-to-end
-------------------------------------------
1. Click the "Test workflow" button (or use "Run once" at the top of the editor)
2. Pick a real or sample email from the trigger preview
3. Watch each step execute:
   • Trigger fires → email data is loaded
   • AI step classifies → returns intent JSON
   • HTTP step POSTs to your webhook → returns {"success": true, "ticketId": N}
4. Open https://portal.risebird.io/SupportTicket in your browser
   → the ticket should appear in the dashboard immediately.

STEP 8 — Turn the workflow ON
------------------------------
1. Toggle the workflow from "Off" to "On" using the switch in the top-right of
   the workflow editor.
2. From now on every new email arriving in your support inbox will automatically:
   a. Be classified by the AI
   b. Create a row in SupportTickets table
   c. Appear in the Risebird Support Ticket dashboard

STEP 9 — Ongoing: move the workflow into the Agent
----------------------------------------------------
If the workflow was created standalone:
1. Open the workflow editor → click the "..." (3 dots) top-right
2. Select "Move to Agent" → choose "Customer Support Email Triage"

================================================================================
SECURITY NOTES
================================================================================
• The webhook endpoint (/SupportTicket/Webhook) is decorated with
  [AllowAnonymous] so Relay can call it without a session cookie.
• Access is controlled by the X-Relay-Secret shared-secret header.
• Generate a strong random secret (e.g. a 32-char UUID or random string).
• Store it in appsettings.json under RelayWebhook:Secret (or better, in
  Azure Key Vault / environment variable) and add the SAME value to the
  Relay HTTP step header.

================================================================================
TROUBLESHOOTING
================================================================================
Problem:  Webhook returns 401 Unauthorized
Fix:      The X-Relay-Secret header in the Relay HTTP step must exactly match
          appsettings.json → RelayWebhook:Secret

Problem:  Webhook returns 400 Bad Request — "Missing required field: sender_email"
Fix:      Check the Relay variable for the sender email.
          In Gmail it is {{trigger.from_email}}.
          In Outlook Mail it may be {{trigger.from.emailAddress.address}}.

Problem:  ClientName shows "Unknown" for a ticket
Fix:      The sender's email was not found in UserList, or their UserList record
          has IsActive = 0.  Add the user to the portal or check IsActive flag.

Problem:  Workflow trigger not firing
Fix:      (a) Confirm the trigger is toggled ON.
          (b) Email triggers in Relay poll every few minutes — wait up to 5 min.
          (c) Check the inbox filter — make sure new emails match the filter.
